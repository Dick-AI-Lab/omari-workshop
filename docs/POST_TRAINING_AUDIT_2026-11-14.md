## 1. Executive Project Summary

"From Pixels to Predictions" is a two-hour OMARI workshop: a Vite/React Distill-style website (7 chapters + presenter mode), six Colab notebooks generated by `scripts/build_notebooks.py`, a Python package `python/omari_us` (data, models, training, evaluation, XAI, export, optional FastAPI server), configs, tests and docs. It compares DenseNet-161, ViT-B/16 and USF-MAE on FETAL_PLANES_DB (6 classes).

**Current state.** All six notebooks were run in Colab (MODE=`full`, T4 GPU; nb05 on CPU) and their outputs were copied into `content/`. 38 training runs exist and **every reported metric recomputes exactly from the saved prediction files**. Test macro-F1 at full labels: DenseNet-161 0.9425, ViT-B/16 0.9410, USF-MAE 0.9403 (seed 0) — **statistically indistinguishable** (Holm-adjusted McNemar p = 1; patient-cluster CIs overlap). A complete website bundle (24 test samples, 3,149 files) was exported and is schema-compatible with the site, but it has **not been installed** into `website/public/experiments/`, so the site currently shows "awaiting artifact" states.

**Headline problems (all CONFIRMED):**
1. **USF-MAE was fine-tuned from `usf_mae_500ep.pth`, not the specified 100-epoch checkpoint** (all 19 USF-MAE runs). MAE reconstructions in the bundle, by contrast, came from `usf_mae_100ep.pth` — the bundle mixes two checkpoints. Configs/docs/website still say 100ep.
2. **`runs/densenet161_finetune_lf1_s0/best.pt` was overwritten** by an interrupted sweep rerun; it no longer matches its `summary.json` checksum. The website bundle's DenseNet XAI and training curve derive from the rerun weights.
3. **Website label-efficiency data is broken either way:** bundle version holds a single frozen point (`configs/export.yaml:40` `label_efficiency_regime: frozen`); the full fine-tune grid exists only in `ART/website_export/label_efficiency.json`, which contains bare `NaN` (invalid JSON in browsers).
4. **`website/src/data/` is not in git** — the unanchored `data/` rule (`.gitignore:23`, also `:11`) ignores `artifacts.tsx`, `imageSource.tsx`, `literature.ts`, `types.ts`. A fresh clone cannot build the site.
5. **`README.md` contains an unresolved merge conflict** (`<<<<<<< HEAD` at line 1, `=======` at line 67, no closing marker), committed in `3ad7b36`.
6. The USF-MAE **pretraining-overlap disclosure is dropped** from the bundle manifest (`models[].notes = null`).
7. The **working-tree notebooks (the ones that produced the results) are uncommitted** and have drifted from the generator; regenerating would revert the run settings.

### 9.2 Suspected / version-dependent
- `torch.amp.GradScaler` needs torch ≥ 2.3 but `requirements.txt` allows ≥ 2.1.
- `gdown --id` may fail with gdown ≥ 5.
- Label-efficiency glob `runs/*_lf*_s*` would include `_demo` runs.
- `scripts/evaluate.py` likely fails locally on absolute `/content` manifest paths without `--data-root`.
- Grad-CAM++ numerical instability on possibly-negative activations; feature maps ReLU'd for display where the network has no ReLU.

### 9.4 Scientific limitations
- **No significant difference** among the three fine-tuned models at full labels; any ranking at 100% would be unsupported. USF-MAE's advantage is clear only at 5% labels (and 1%, with high variance).
- **Pretraining overlap:** FETAL_PLANES_DB images (unlabelled) are in USF-MAE's SSL corpus (per project config; not independently verified). Test images were seen transductively during pretraining — not supervised label leakage, but a potential advantage, especially at low label budgets and on the Voluson S10 scanner (USF-MAE 0.937 vs DenseNet 0.922 acc). The 500ep checkpoint saw this data longer.
- **Confounding:** model differences bundle architecture, pretraining data/objective, and fine-tuning recipe (DenseNet wd 1e-4 / warmup 1 vs USF-MAE wd 0.05 / warmup 3 / layer decay; ViT bicubic + 0.5 norm vs USF-MAE nearest + ImageNet norm). No hyper-parameter search; unequal seeds (1 vs 3). Results cannot be attributed to architecture alone.
- **Scanner shift:** Voluson S10 = 1,071 test images, 11 train, 0 val; validation (87 patients) cannot reflect it.
- **Near-duplicates:** 2,685 train/val↔test pairs (different patients, 65 exact hash matches) touching 320 test images; no visible accuracy inflation on the 241 same-label cases, but the docs' claim that such pairs are "rare" is false.
- **Faithfulness:** n = 30, no significance test; attention rollout ≈ random and USF-MAE `vit_gradcam` worse than random — yet the latter is what the perturbation panel displays for USF-MAE.
- **Determinism:** per-run seeding, but no cuDNN determinism/seeded workers, AMP on (a USF rerun did reproduce exactly in practice).
